# Hero Lineup 在线逻辑开发规格

> 目标：把 `https://cq-zys.cn/hero-lineup` 的前端可观察业务逻辑、属性计算和战斗模拟规则，整理成不依赖原网页代码、可直接交给程序开发的实现规格。
>
> 证据基线：`cq-zys-hero-lineup-snapshot-2026-07-25/` 中的页面、JavaScript bundle 和 TextAsset JSON。图片只按资源 ID 使用，不参与逻辑解释。

## 1. 范围、结论与证据强度

本规格覆盖：

1. 体系、英雄、勇士、任务分组和任务的状态模型；
2. 英雄与勇士的等级、种子、卡牌、阶级和魂计算；
3. 六槽装备、勇士双槽装备、品质、星能铸造、超越、元素核心和精魂核心；
4. 技能选择、技能族升级、技能互斥和通用技能效果；
5. 冒险地图、难度、强化道具、精英怪、泰坦楼层、环境词条和元素屏障；
6. 勇士队长技、光环、神器和职业特殊状态；
7. 10,000 次 Monte Carlo 战斗模拟、失败重试和结果统计；
8. 阵容排序、成员占用、装备需求统计、配置导入导出和服务端保存边界。

证据强度：

- **A：前端 bundle 直接存在条件、公式和执行顺序。** 应逐项等价实现。
- **B：bundle 给出解释方法，具体参数来自 JSON。** 算法固定，数值必须数据驱动。
- **C：产品或离线实现约定。** 不得标记成线上精确逻辑。

核心结论：线上代码经过生产压缩和变量改名，但不是不可恢复的加密。页面前端承担的核心计算逻辑可以还原到开发级规格；服务端私有实现、数据库约束、密钥和真实随机历史结果不能仅凭静态前端恢复。

## 2. 全局实现原则

### 2.1 数据驱动

除明确列出的特殊职业、勇士和神器分支外，所有数值必须从 JSON 读取，不能把当前数值硬编码进业务代码。

主要数据源：

| 数据 | 用途 |
|---|---|
| `classes.json` | 职业类型、六槽类型、自带技能、技能槽等级、晋升关系 |
| `heroes.json` | 勇士基础属性、阶级成长、队长技能 |
| `items.json` | 装备、核心、品质前基础值、亲和、星能、超越、装备技能 |
| `skills.json` | 英雄技能、神器、职业 innate、物品技能 |
| `levels.json` | 等级对应最大装备阶数 |
| `qmodifiers.json` | Booster、勇士队长技、精英怪、任务和泰坦词条修正 |
| `quests.json` 及地图数据 | 怪物、屏障、AOE、回合、地图分类和难度 |
| `texts_zh.json` | 中文显示，不参与数值主键 |
| `items_type_dict.json` | 装备类型显示名 |

所有实体使用稳定 ID 关联，中文名只用于展示和排序末级，不可作为计算主键。

### 2.2 数值类型

- 中间百分比统一用小数，例如 `0.25` 表示 25%。
- 页面面板中的回避、暴击率可能以百分数保存，例如 `25` 表示 25%；进入概率判断前除以 100。
- HP、攻击、防御、伤害和元素值最终为整数。
- 不得把 `floor`、`round`、`ceil` 合并到流程末尾；每个取整点都是规则的一部分。
- JavaScript 的 `Math.round(x)` 对非负数等价于 `floor(x + 0.5)`。本域数值均应先限制为非负，再按此语义取整。

### 2.3 输入容错

- 缺失数值字段按 0 处理，但主实体不存在应产生错误。
- 非法装备、技能和附件不参与属性汇总，并返回稳定问题码。
- 导入旧数据时先标准化，再校验；禁止让旧字段直接进入模拟器。
- 所有概率进入随机判断前按对应上限夹取。

## 3. 领域状态模型

### 3.1 体系

一个体系至少包含：

- 体系 ID、名称、描述、公开状态、短口令；
- 英雄列表；
- 勇士列表；
- 英雄装备映射；
- 勇士装备映射；
- 任务分组；
- 英雄和勇士分别保存的已有装备数量；
- 更新时间、未保存状态和导入来源标记。

未登录时创建一个本地默认体系。登录后从 `/api/hero-lineup/systems` 读取服务器体系。服务端返回可能是普通 JSON，也可能包含 `encrypted` 字符串；客户端先解密再解析。

### 3.2 英雄

英雄构建至少包含：

- 实例 ID；
- 职业 ID；
- 等级 `1..50`；
- 单一网页种子值 `0..80`，或兼容的 HP/攻击/防御独立种子；
- 卡牌等级 `0..3`；
- 最多四个可选技能族 ID；
- 六个固定装备槽；
- 是否按泰坦塔/墓环境预览。

职业晋升由职业 ID 本身表达，例如 `knight` 与 `lord` 是两个职业实体；不能用独立布尔值替代职业 ID。

### 3.3 勇士

勇士构建至少包含：

- 勇士 ID；
- 等级 `1..50`；
- 阶级 `1..71`，显示为 `1..11`、`11+1..11+60`；
- 种子 `0..80`；
- 卡牌等级 `0..3`；
- 勇士之魂布尔值；
- 使魔槽 `xf`；
- 光环之歌槽 `xx`。

勇士没有英雄的四个可选技能槽。其队长技由 `heroes.json` 的技能节点和阶级决定。

### 3.4 装备槽

每个装备槽保存：

- 主装备 ID；
- 品质；
- 星能铸造开关；
- 超越开关；
- 元素核心 ID，可空；
- 精魂核心 ID，可空。

英雄必须是六槽固定映射：武器、身体、手、头、脚、饰品。具体允许类型读取职业 `slot1..slot6`，类型可为单值或多值。勇士只允许 `xf` 和 `xx`。

### 3.5 任务

任务至少包含：

- 任务 ID、所属分组；
- 类别：`normal`、`goldcity`、`titantower`、`flash`；
- 地图/怪物 ID 和难度；
- 成员 ID 列表；
- 最多一个勇士；
- Booster 等级；
- 精英怪类型；
- `selectedElement`：自动、固定六元素之一或 `force`；
- 泰坦楼层、墓穴楼层、祝福灯笼、泰坦词条；
- 最近一次模拟结果和模拟输入快照。

创建新任务分组时同时创建一个默认任务。单体系任务上限为 48。

## 4. 基础等级曲线

英雄和勇士的 HP、攻击、防御共用等级曲线。输入为：

- `S`：1 级值；
- `V40`：40 级值；
- `V50`：50 级值；
- `L`：等级。

规则：

1. `L <= 1`：`round(S)`。
2. 把等级夹在 `1..50`。
3. `2..40` 级：
   - 单位增量 `u = (V40 - S) / 100`；
   - 步数 `n = L - 1`；
   - 权重  
     `w = min(n,8)`  
     `+ 2 × max(min(n,19)-8,0)`  
     `+ 3 × max(min(n,29)-19,0)`  
     `+ 4 × max(n-29,0)`；
   - 结果 `round(S + u × w)`。
4. `41..50` 级：
   - `r = (L - 40) / 10`；
   - 结果 `round(V40 + (V50 - V40) × r)`。

回避、暴击率、暴击倍率和威胁值直接读取职业/勇士数据，不走等级曲线，除非相应数据表另有显式成长字段。

## 5. 种子与卡牌

### 5.1 种子

网页单一种子 `s` 同时产生：

- HP `+s`；
- 攻击 `+4s`；
- 防御 `+4s`。

兼容独立种子时，每个独立值覆盖对应网页单一值：

- HP `+seedHp`；
- 攻击 `+4 × seedAtk`；
- 防御 `+4 × seedDef`。

如果领域允许回避、暴击和暴伤种子，则它们是对应面板值的直接加法，不能乘 4。

### 5.2 卡牌

卡牌倍率：

| 等级 | 倍率 |
|---:|---:|
| 0 | 1.00 |
| 1 | 1.05 |
| 2 | 1.10 |
| 3 | 1.25 |

卡牌乘 HP、攻击、防御，不乘回避、暴击、暴伤、威胁、元素值和回复。

## 6. 装备合法性

主装备加入计算前依次验证：

1. 槽位存在且未重复；
2. 装备 ID 存在；
3. 类型匹配职业槽位或勇士槽位；
4. 装备 `restrict` 为空，或包含职业 ID、职业类型、`*`；
5. 装备等级不高于角色等级；
6. 装备阶数不高于 `levels.json` 中当前等级的 `etier`；
7. 元素核心存在且含 `elements`；
8. 精魂核心存在且含 `skill`。

非法主装备整件排除；无效附件只排除附件，并产生问题码。

英雄六槽额外规则：

- 同一英雄最多一件神器；
- 神器护符与任何武器组合时给出冲突；
- 特定物品类型依赖武器类型的限制按 `itemTypes` 数据校验；
- 内置附件优先，用户不能覆盖。

## 7. 单件装备属性

### 7.1 品质

品质倍率：

| 品质 ID | 倍率 |
|---|---:|
| normal/common | 1.00 |
| superior/uncommon | 1.25 |
| flawless | 1.50 |
| epic | 2.00 |
| legendary | 3.00 |

### 7.2 超越

超越开启时，读取 `supgrade4..supgrade6` 的表达式：

- `baseStats*x`：累计乘入超越基础倍率；
- `atk+x`、`def+x`、`hp+x`：对应原始属性加固定值；
- `eva+x`、`crit+x`：对应次级属性加固定值。

主属性的品质前原始值：

- `rawAtk = item.atk + transcendAtkFlat`；
- `rawDef = item.def + transcendDefFlat`；
- `rawHp = item.hp + transcendHpFlat`。

然后：

- `qualityAtk = round(rawAtk × qualityMultiplier)`；
- `qualityDef = round(rawDef × qualityMultiplier)`；
- `qualityHp = round(rawHp × qualityMultiplier)`。

回避和暴击只加超越固定值，不乘品质。

### 7.3 元素和精魂核心的属性注入

核心可包含 `atk/def/hp`。对每项主属性：

1. 判断亲和：
   - 主装备 `elementAffinity` 包含元素核心元素，或包含 `all`；
   - 主装备 `spiritAffinity` 包含精魂技能族；
   - 内置 `lTag2/lTag3` 视为亲和；
2. 亲和倍率为 1.5，否则为 1；
3. 核心贡献  
   `coreBonus = min(floor(coreStat × affinityMultiplier), itemRawStat)`。

注意封顶比较对象是品质前、含超越固定值的主装备原始属性，不是品质后的值。

### 7.4 星能铸造

星能开关开启时，顺序读取 `upgradeShiny1..upgradeShiny5`。只处理 `baseStats*x`，累计相乘得到 `shinyMultiplier`。

### 7.5 星能和超越合并

二者不是相乘，而是把各自相对 1 的增量相加：

`combinedBaseMultiplier = 1 + (shinyMultiplier - 1) + (transcendMultiplier - 1)`

对已包含品质和核心注入的主属性应用：

- `finalItemAtk = round((qualityAtk + coreAtkBonus) × combinedBaseMultiplier)`；
- 防御、HP 同理。

### 7.6 内置附件

- `lTag2` 存在时，它覆盖用户选择的元素核心；
- `lTag3` 存在时，它覆盖用户选择的精魂核心；
- 内置附件视为亲和；
- 批量附魔不能改写内置附件。

## 8. 精魂技能

### 8.1 技能族选择

精魂核心的 `skill` 字段给出技能族：

- 主装备对该技能族有亲和时优先读取 `${family}_plus`；
- 否则读取 `family`；
- 若 `plus` 实体不存在则回退普通实体。

物品类型为 `xi` 时，精魂技能平坦效果倍率为 2，否则为 1。

### 8.2 平坦效果

按技能字段加入单件装备：

- `atkAbs`、`defAbs`、`hpAbs`；
- `evasion`、`critical`、`critMult`；
- `aggro`；
- `regen`。

这些字段按各自数值语义直接加法；`xi` 时乘 2。

### 8.3 墓生灵

技能族为 `i_tomb` 时：

1. 亲和选择 `i_tomb_plus`，否则 `i_tomb`；
2. 倍率为 `1 + skill.item`；
3. 若处于泰坦塔或泰坦之墓预览，改为 `1 + 2 × skill.item`；
4. 对本件装备的攻击、防御、HP 分别乘该倍率并 `round`。

### 8.4 装备类型技能

若技能包含 `itemTypes`：

1. 主装备类型必须匹配列表或 `*`；
2. 百分比取 `skill.item`；
3. `affectSecStat=true` 时，攻击、防御、HP 全部乘 `1+item` 后分别 `round`；
4. 否则只强化主属性。

主属性判定：

1. 攻击大于 0 且不小于防御和 HP，则攻击为主；
2. 否则 HP 大于防御，则 HP 为主；
3. 否则防御为主。

## 9. 英雄技能

### 9.1 槽位

最多四个槽。第 `N` 槽读取职业 `sklNLv`：

- 值为 0：槽位不存在；
- 英雄等级小于该值：槽位锁定；
- 锁定槽里的旧导入技能不生效，并产生警告。

### 9.2 可选范围

技能 `classes` 必须为：

- `*`；
- 当前职业 ID；
- 当前职业类型。

技能族不能与职业 innate 相同。一个构建中：

- 同一 `family` 只能出现一次；
- 非空 `category` 只能出现一次。

### 9.3 实际技能阶

配置保存技能族的一阶 ID，不直接保存实际阶。

1. 基础职业，即 `titanClass` 指向晋升职业，最高 3 阶；
2. 晋升职业，即 `titanClass=null`，最高 4 阶；
3. 从最高阶向 1 阶查找 `${family}${tier}`；
4. 英雄总元素值必须不小于该技能的 `elements` 门槛；
5. 选择第一个满足门槛的实体；
6. 若没有更高阶满足条件，回退导入的一阶实体。

### 9.4 通用百分比

把 innate 和所有有效已选技能的下列字段累加：

- `atk`、`def`、`hp`：比例；
- `evasion`、`critical`、`critMult`、`aggro`、`regen`：加法。

应用主属性：

- 攻击 `floor(baseAtk × (1 + atkPercent))`；
- 防御 `floor(baseDef × (1 + defPercent))`；
- HP `round(baseHp × (1 + hpPercent))`。

## 10. 英雄最终面板流水线

开发实现必须固定以下顺序：

1. 由职业数据计算等级 HP、攻击、防御；
2. 加种子；
3. 逐槽验证装备；
4. 计算每件装备品质、附件、星能、超越和精魂技能；
5. 汇总有效装备主属性和次级属性；
6. 计算总元素值；
7. 依据总元素值解析 innate 和已选技能的实际阶；
8. 应用技能平坦值、装备类型效果和百分比；
9. 应用卡牌倍率；
10. 输出：
    - HP：`round(max(1, hp))`；
    - 攻击：`floor(max(0, atk))`；
    - 防御：`floor(max(0, def))`；
    - 回避：面板概率 ×100；
    - 暴击率：面板概率 ×100；
    - 暴击倍率：原始倍数；
    - 威胁、元素值、每回合回复。

`baseDefense` 供战斗特殊公式使用：它包含卡牌倍率，但截取在技能百分比之前。实现时应保留显式字段，不能事后反推。

## 11. 元素值

有效元素核心的 `elements` 解析为 `element + amount`。

只有以下情况计入：

- 核心元素等于单位元素；
- 单位元素为 `all`。

单件元素值：

1. 基础为核心 `amount`；
2. 主装备 `elementAffinity` 包含该元素：
   - 核心阶数 `<12` 加 5；
   - 核心阶数 `>=12` 加 10；
3. 若亲和列表包含 `all`，加 5；
4. 无亲和不加。

不匹配单位元素的核心对面板元素值贡献为 0。

## 12. 勇士面板

### 12.1 等级

勇士 HP、攻击、防御使用第 4 节相同等级曲线。

### 12.2 阶级

对索引 `1..11`：

- 若 `rank > index`，读取 `upgNN`；
- 表达式 `stat+x` 表示加入 `storyHp/storyAtk/storyDef × x`；
- 每项阶级奖励分别 `floor`。

若 `rank > 12`，把 `upg11` 额外重复 `rank - 12` 次。

### 12.3 勇士之魂

开启时：

1. 读取 `upgTitan`；
2. 加入 `floor(storyStat × upgTitanMultiplier)`；
3. 已累计的阶级奖励再乘 1.5 并 `floor`。

### 12.4 元素值阶梯

勇士阶级对应元素值：

| Rank | 元素值 |
|---:|---:|
| 1–4 | 0 |
| 5 | 15 |
| 6–7 | 30 |
| 8 | 45 |
| 9 | 60 |
| 10–11 | 80 |
| 12–13 | 90 |
| 14–15 | 100 |
| 16–19 | 110 |
| 20+ | 125 |

### 12.5 后续流水线

阶级奖励之后，勇士依次应用：

1. 种子；
2. 使魔和光环装备；
3. 装备精魂效果；
4. 固定队长技自身可用字段；
5. 卡牌；
6. 最终取整。

## 13. 勇士队长技

一支队伍最多一个勇士生效。若存在多个异常旧数据，选择 `heroesData` 中能找到且 `event=null` 的第一个勇士。

先统计英雄职业类型数量：fighter、rogue、spellcaster。神器盗贼帽会让佩戴者不接受勇士给予的修正。

| 勇士 | 效果 |
|---|---|
| Argon | 全队攻击、防御比例 |
| Ashley | 全队攻击、防御；Boss 时两者乘 `bossMult` |
| Bjorn | 暴伤加到各单位；快闪任务按 `FlashQuestModMult` 缩放；勇士 HP/攻击加成也按该倍率 |
| Donovan | spellcaster 数量乘攻击加成；fighter 数量乘 HP 加成；rogue 数量乘每人回避和暴击加成 |
| Hemma | HP 加成；记录 Hemma 位置和每回合冒险转攻击倍率 |
| Lilu | HP 加成；并提供固定每回合回复 |
| Malady | 攻击加成；每人回避和暴击 |
| Polonia | 防御加成；每人回避 |
| King | 攻击、防御、HP |
| Sia | 攻击 |
| Yami | 每人回避和暴击 |
| Rudo | 限时暴击率；元素屏障值倍率 |
| Leather | 每次攻击独立生成 `[0, randomAttackBonus)` 的均匀随机攻击比例 |

Soldier/Mercenary 类 innate 若含 `championStatBonusMultiplier`，只放大勇士给予该单位的修正。

## 14. 光环之歌

解析光环物品对应技能后：

- 全队攻击、防御、HP 比例分别累加；
- 每个单位加入 `hpAbs`；
- 每个单位加入回避、暴击率、暴击倍率和回复；
- 神器盗贼帽佩戴者不接受上述光环修正。

## 15. 神器

### 15.1 通用

- 英雄六槽最多一件神器；
- 神器效果按技能 ID 判断；
- 盗贼帽会阻断勇士和光环给予佩戴者的修正；
- 神器冒险经验转攻击只作用于实际佩戴神器帽的英雄本人，不作用于队友和勇士。

## 18. 泰坦楼层

楼层夹在 `1..500`。

1..30 层：

- `floor <=16`：HP% `5 + (floor-1)×19/3`；
- `floor >16`：HP% `100 + (floor-16)×20/3`；
- `floor <=16`：攻击% `5 + (floor-1)×7/3`；
- `floor >16`：攻击% `40 + (floor-16)×4`；
- `floor <=11`：防御% `5 + (floor-1)×1.5`；
- `floor >11`：防御% `20 + (floor-11)`。

31 层起：

- HP% `200 + (floor-31)×10`；
- 攻击% `100 + (floor-31)×10`；
- 防御% `40 + (floor-31)×2`。

泰坦诅咒减免：

`retained = 1 - clamp(reduction, 0, 1)`

三项楼层百分比分别乘 `retained` 后再应用。

## 19. 战斗准备固定顺序

1. 从英雄/勇士面板构造战斗单位；
2. 神器权杖调整初始 HP；
3. 解析唯一勇士队长技；
4. 解析光环；
5. 应用 Booster；
6. 合并精英、任务和泰坦词条；
7. 计算怪物永久和限时修正；
8. 计算每个单位攻击、HP、防御倍率；
9. 应用队长技、光环、塔词条和神器冒险经验加成；
10. 预计算怪物普通和暴击对每个单位的伤害；
11. 解析元素屏障，得到整场英雄伤害倍率；
12. 初始化职业状态、威胁、攻击顺序和一次性标记；
13. 进入逐回合循环。

任何实现若改变此顺序，都可能得到不同结果。

## 20. 防御阈值伤害

设单位最终防御为 `D`，任务阈值为 `T`。

普通伤害倍率：

- `0..T`：从 1.5 线性降到 1；
- `T..2T`：从 1 线性降到 0.5；
- `2T..4T`：从 0.5 线性降到 0.3；
- `4T..12T`：从 0.3 线性降到 0.25；
- `>12T`：0.25。

普通最终伤害：`round(monsterDamage × multiplier)`。

暴击：

- `D <= T`：防御倍率从 1.5 线性降到 1；
- `D > T`：防御倍率 1；
- 最终  
  `round(monsterDamage × monsterCritMultiplier × (1 + critMultBonus) × defenseMultiplier)`。

无 `tdef` 时才允许使用兼容公式 `damage × 100 / (100 + defense)`。

## 21. 元素屏障

### 21.1 强制

`selectedElement=force`：

- 直接视为破盾；
- 屏障伤害倍率为 1；
- 忽略屏障类型和 HP。

### 21.2 固定元素

1. 匹配元素单位全额加入元素值；
2. `all` 单位按 50% 加入；
3. 有 Rudo 时，总值乘屏障倍率后 `floor`；
4. 若屏障 HP 大于 0 且总值小于屏障 HP，队伍伤害 ×0.2，否则 ×1。

### 21.3 随机元素

1. 分别汇总 fire、water、earth、air、light、dark；
2. `all` 对每个候选元素贡献 50%；
3. Rudo 倍率对每个汇总值应用并 `floor`；
4. 取最大值；
5. 与 `barrierPower` 比较；
6. 未达到则 ×0.2，否则 ×1。

屏障整场只解析一次，不在每回合重新扣减。

## 22. 战斗状态

每个单位至少维护：

- 当前 HP、最大 HP；
- 累计伤害；
- 是否存活；
- 幸存概率及是否已消耗；
- 必暴、必闪；
- Sensei 失效回合；
- Conquistador 连暴加成；
- Berserker/Jarl 阶段；
- Ninja/Sensei 暴击与闪避加成；
- Hemma 累计攻击加成；
- 闪避上限；
- 是否神器禁闪。

全局至少维护：

- 怪物当前/最大 HP；
- 当前回合，最大 499；
- 当前存活人数；
- Lord 一次代死是否可用；
- Shark 是否激活；
- Dinosaur 是否激活；
- Rudo 当前暴击加成；
- 随机攻击顺序；
- 威胁累计边界。

## 23. 每回合完整状态机

循环条件：回合 `<499`、怪物 HP `>0`、至少一名单位存活。

### 23.1 回合开始

1. 回合数 +1；
2. Sensei 若 `lostRound == currentRound-2`，恢复 innate 的暴击和闪避加成；
3. 计算泰坦词条对每人的本回合闪避变化；
4. 若有单位死亡或威胁变化，重建目标累计边界；
5. 汇总本回合怪物限时攻击和暴击修正；
6. 计算单体伤害回合倍率：  
   `(1 + perRound × (round-1)) × (1 + timedDamageDelta)`；
7. 怪物本回合暴击率：  
   `permanentCrit + originalBaseCrit × timedCritDelta`。

### 23.2 怪物选择 AOE 或单体

只有存活数大于 1 时才允许 AOE。

`random < finalAoeChance` 进入 AOE，否则单体。

### 23.3 AOE

对所有存活单位逐个处理：

1. 最终闪避率  
   `baseEvasion + berserkerStage×evaBuf + focusEvasion + timedTowerEvasion`；
2. 夹到职业上限：普通 0.75，Pathfinder 0.78；
3. 神器靴只关闭普通概率闪避；若本单位已有必闪标记，仍判为闪避成功；
4. AOE 不暴击，不吃单体每回合增伤；
5. 伤害为 `ceil(precomputedNormalDamage × aoeRatio)`；
6. Dancer/Acrobat 闪避成功后，下次攻击必暴；
7. 未闪避则扣 HP；
8. 致死时按第 24 节处理；
9. Sensei 实际受伤时记录失效回合。

### 23.4 单体

目标概率只使用存活单位威胁值：

1. 总威胁为存活单位 `aggro` 之和；
2. 为每个位置生成“从该位置到末尾”的累计值除以总威胁；
3. 随机后从数组末尾逆向选择首个命中边界的单位。

目标处理：

1. 计算闪避；
2. 闪避则处理 Dancer/Acrobat 必暴；
3. 未闪避时，怪物暴击概率还要加入目标对负闪避的惩罚：当计算闪避为负时，额外暴击率为 `-0.25 × evasion`；
4. 暴击用预计算暴击伤害，否则普通伤害；
5. 两者都乘本回合单体伤害倍率并 `round`；
6. 扣 HP，处理致死；
7. Sensei 实际受伤时失效。

### 23.5 Hemma

仅 Hemma 存活时：

1. 读取 `hemmaleader{skillLevel}`；
2. 阈值为 `hpConsumption`；
3. 候选只含英雄，不含勇士和 Hemma；
4. 候选必须存活且 `currentHp/maxHp > threshold`；
5. 按当前 HP 比例降序，选择最高者；
6. 普通抽血量为 `threshold × target.maxHp`；
7. 目标有盗贼帽时抽血量为 0；
8. 目标 HP 减抽血量，下限 0；
9. Hemma 累计攻击修正增加 `atkFromAdvMult ×100` 个百分点；
10. Hemma 回复 `hpReceived`，不超过最大 HP；
11. 若目标是 Sensei 且抽血量大于 0，视为本回合受伤并使 innate 失效。

### 23.6 职业状态刷新

- Berserker/Jarl 依据三个 HP 阈值更新 0/1/2/3 阶段；
- Ninja 只要当前 HP 低于最大 HP，暴击和闪避加成立即永久清零；
- Sensei 在本回合受伤时暴击和闪避加成清零。

### 23.7 第一回合

怪物攻击阶段结束后：

- Swordmaster、Samurai、Daimyo 的下一次攻击必暴；
- Daimyo 初始必闪在此时清除；
- 这三类第一回合攻击忽略元素屏障伤害衰减。

### 23.8 单位攻击

攻击顺序每场开始时对全部单位索引执行 Fisher–Yates 洗牌，整场沿用该顺序。

每个存活单位：

1. 用随机数与怪物回避比较，确定命中；
2. 基础攻击修正加入：
   - Boss 时 Mundra；
   - Shark 激活时 sharkBonus；
   - Dinosaur 激活时 dinosaurBonus；
   - Berserker/Jarl 阶段攻击；
   - Hemma 累计攻击；
3. 最终攻击由基础攻击、修正、墓地固定修正和战前攻击倍率计算；
4. Leather 每次命中独立产生均匀随机比例，并对攻击 `round`；
5. 暴击率：
   - 神器剑存在时使用覆盖值；
   - 否则基础暴击 + Ninja/Sensei + 当前 Rudo；
   - 必暴直接覆盖随机结果；
6. 暴击伤害 `round(attack × (critMult + consecutiveCritBonus))`；
7. Conquistador：
   - 暴击后连暴加成 `+0.25`，上限 1；
   - 非暴击重置为 0；
8. 除第一回合三种职业外，乘屏障倍率并 `round`；
9. 若怪物有 `dmgRed`，再乘 `1-dmgRed` 并 `round`；
10. 扣怪物 HP，累计该单位伤害；
11. Dark Knight/Death Knight 命中后，若怪物剩余 HP 低于最大 HP 的 10%，立即斩杀；
12. 怪物 HP 低于 `i_shark.monsDmgBuf × maxHp` 时，Shark 永久激活；
13. 消耗本单位必暴标记。

每轮单位攻击完成后，`dinosaurActive=0`，因此 Dinosaur 攻击加成只覆盖第一轮单位攻击阶段。

### 23.9 Rudo 到期

若存在 Rudo，读取 `rudoleader{skillLevel}.duration`。本回合单位攻击结束后，当 `currentRound >= duration`，把当前 Rudo 暴击加成清零；因此边界回合的攻击仍可享受加成，下一回合开始不再享受。屏障倍率已在战前使用，不受此到期影响。

### 23.10 治疗

怪物死亡则跳过治疗。

普通治疗：

- 只给存活单位；
- `currentHp = min(currentHp + regen, maxHp)`。

存在 `healdrain`：

- 英雄和勇士不回复；
- 计算全队本轮本应获得的有效回复总和；
- 怪物回复该总和，不超过怪物最大 HP。

治疗后再次刷新 Berserker/Jarl 阶段，最后重算存活数。

## 24. 致死、幸存和 Lord

单位 HP 降到 0 或以下：

1. 先随机判断该单位 `surviveChance`；
2. 成功：
   - HP 设为 1；
   - 该单位本场幸存概率清零，不能重复触发；
3. 失败后再判断 Lord：
   - 队伍有存活 Lord；
   - 本场代死尚未使用；
   - 受害者不是 Lord；
4. 满足时恢复受害者本次伤害，并让 Lord 承受同额伤害；
5. Lord 若因此致死，也有自己的幸存概率判断；
6. Lord 代死标记无论结果都变为已使用；
7. 两者都失败才减少存活人数并标记威胁需重建。

顺序必须是“受害者自身幸存 → Lord”，不能相反。

## 25. 结果判定与单场输出

- 怪物 HP `<=0`：成功；
- 所有单位死亡：失败；
- 达到 499 回合且怪物仍存活：失败。

单场输出至少包括：

- 是否成功；
- 使用回合；
- 每个单位累计伤害；
- 每个单位是否存活；
- 每个单位最终 HP；
- 怪物剩余 HP。

## 26. Monte Carlo 与重试

### 26.1 主模拟

每次点击“测试冒险”固定运行 10,000 个原始样本。线上使用 `Math.random`，因此同一输入可出现轻微波动。

聚合：

- 总成功率 = 成功原始样本数 / 10,000；
- 成功回合平均、最小、最大只统计成功场；
- 无成功场时三者为 0；
- 单位存活率 = 该单位存活场数 / 10,000；
- 单位平均伤害 = 该单位总伤害 / 10,000；
- 单位平均剩余 HP = 该单位最终 HP 总和 / 10,000。

### 26.2 Timekeeper / Chronomancer

只对第一次失败的样本立即执行第二场：

- Chronomancer 使用原配置；
- Timekeeper：
  - 原来无 Booster 时，第二场使用一级 Booster；
  - 原来有 Booster 时，在原档基础上叠加一级对应加成；
- 总体成功率的分母仍是原始 10,000；
- 第二场独立统计的分母是第一次失败数；
- 单位总体存活等指标也按原始样本数归一。

### 26.3 显示

- 卡片成功率显示三位小数；
- 详情展示成功率、平均/最少/最多成功回合和失败数据；
- 每名成员展示存活率、平均伤害、平均剩余 HP；
- 每次新测试覆盖旧结果。

离线产品若引入固定随机种子，必须标记为可复现增强，不得声称与线上随机序列一致。

## 27. 装备需求统计

统计范围：

- 英雄页统计体系全部英雄；
- 勇士页统计体系全部勇士；
- 不按任务是否上阵过滤。

需求键：

`category_itemId_quality`

其中 category 为主装备、元素核心、精魂核心。核心沿用所在主装备槽品质。

已有数量键：

`itemId_quality`

输入规则：

- 允许输入框暂时为空；
- 非空转整数并 `floor`；
- 下限 0；
- 剩余 `max(required-owned,0)`。

排序：

1. 主装备；
2. 元素核心；
3. 精魂核心；
4. 品质从传奇到普通；
5. 阶数降序；
6. 中文名。

弹窗开启时复制库存草稿，关闭时一次性回写体系。

## 28. 配置导入导出

### 28.1 单英雄/勇士

- 导出生成配置字符串，不以中文名作为主键；
- 导入先解码，再取职业/勇士 ID、等级、种子、卡牌、技能和装备；
- 不存在、超等级、不匹配职业或重复的装备/技能被过滤；
- 导入完成必须给出过滤数量和首个警告；
- 勇士导入前清理旧编辑状态。

### 28.2 体系

- 登录用户可创建、编辑、删除和保存体系；
- 短口令从 `/api/hero-lineup/systems/shortcode/{code}` 导入；
- 导入体系应复制为用户可编辑对象，不直接共享原对象引用；
- 删除需二次确认；
- 未登录不得调用保存；
- Token 只从本地登录状态读取，不进入导出文件。

### 28.3 本地偏好

已确认本地键：

- `heroLineup_taskMemberPickerAllMembers`；
- `heroLineup_templateDisclaimerAcknowledged`；
- `hero_lineup_anonymous_id`；
- 登录 `token`、`role`。

这些偏好不应混入可分享阵容配置。

## 29. 接口边界

前端已观察到的接口：

- `GET /api/hero-lineup/systems`
- `POST /api/hero-lineup/systems`
- 体系编辑和删除接口
- `GET /api/hero-lineup/systems/hot`
- `GET /api/hero-lineup/systems/shortcode/{code}`
- 英雄模板读取、创建、删除接口
- 英雄排行和泰坦墓排行记录接口

静态前端只能确定：

- 请求方法、可见字段、Token 头和客户端错误处理；
- 不能确定数据库结构、服务端加密密钥、权限查询和防作弊实现。

因此服务端应按前端契约重新实现，并额外执行完整输入校验，不能信任客户端计算结果。

## 32. 尚不能从前端静态资源证明的部分

以下内容不应伪称已还原：

- 服务端加密和解密密钥；
- 热门体系排行的服务端评分与反作弊；
- 排行记录的后台去重、审计和封禁逻辑；
- 用户账户、权限和数据库事务；
- 线上过去某次模拟使用的随机数序列；
- hero-lineup 页面没有入口的全局星图/技能树系统。

除此之外，本规格所列面板、任务和模拟逻辑均来自当前快照的可执行前端或其加载数据，可作为独立重开发基线。
